Tier 2 — Create, test, deploy, invoke

The AgentCore CLI takes you from an empty folder to a deployed agent in four commands. Learn the loop first; migration in Tier 3 reuses every step of it.

The four-command loop

The whole lifecycle is create → dev → deploy → invoke. You scaffold a project, run it on your machine, push it to AWS, then call the deployed version.

Primer: two ways to build the same agent

AgentCore gives you two starting points, both driven by the same CLI:

Managed harness. You declare the agent in config — model, prompt, tools, memory — and AgentCore runs the reasoning loop for you. No orchestration code. This is the fastest route from idea to a running agent, and the default recommendation unless you have a reason not to use it.

Code-based agent. You own the loop yourself using a framework such as Strands Agents, LangGraph, Google ADK, or OpenAI Agents. Choose this when you have existing agent code to bring across or orchestration the harness can't yet express.

This tier uses a code-based Python agent with Strands so the mechanics are visible. Keep the harness in mind — Tier 3 weighs the two for migration.

Do it

Step 1 · Scaffold
agentcore create
cd my-project

An interactive wizard walks you through framework, language, and model provider. To skip the prompts and take Python + Strands + Bedrock with no memory, use:

agentcore create --defaults

create initialises a git repository by default. If git isn't installed or your config errors out, add --skip-git.

Step 2 · Test locally
agentcore dev

This starts a local development server that watches for file changes and exposes a local invocation endpoint. In a second terminal, send it a prompt:

agentcore invoke "What can you do?" --stream

--stream shows the response as it's generated. If your provider needs an API key (OpenAI, Anthropic, Gemini), set it in agentcore/.env.local before this step.

Step 3 · Deploy to AWS
agentcore deploy

The CLI uses AWS CDK to provision the AgentCore Runtime resources and push your agent. This is where your aws configure credentials and region matter.

Step 4 · Invoke the deployed agent
agentcore invoke "Summarise today's top task" --stream

With no local dev server running, invoke calls the deployed Runtime endpoint instead of localhost. Same command, different target — that's the point.

Remember

After you add or remove resources (Tier 3), run agentcore deploy again to apply the change in AWS. The config on disk and the resources in AWS only match after a deploy.

Observability, for free

The scaffolded project pulls in the OpenTelemetry distribution as a dependency, so AgentCore Runtime collects traces and logs automatically. To view them, enable CloudWatch Transaction Search for your account, then inspect traces in CloudWatch. You don't wire this up by hand — you turn it on and read it.
